# 강의 소개 사이트 — 사용법과 배포 안내

고려대학교 교과목 강의 소개용 정적 웹사이트입니다. 서버나 설치 없이 브라우저에서 바로 열립니다.

## 1. 폴더 구성

| 파일 | 역할 |
| --- | --- |
| `index.html` | 사이트 뼈대. 이 파일을 열면 사이트가 보입니다. |
| `config.js` | **사이트의 모든 내용**(글, 일정, 메뉴, 공지 등). 내용은 여기만 고치면 됩니다. |
| `styles.css` | 디자인. 색을 바꾸려면 맨 위 `:root` 안의 값을 고칩니다. |
| `app.js` | 화면을 그리고 움직이는 코드. |
| `admin.js` | 관리자 화면 코드. |
| `README.md` | 이 안내 문서. |
| `.claude/` | 제작 도구의 미리 보기 설정. 사이트와 무관하며 배포할 때 빼도 됩니다. |

## 2. 사이트 열어 보기

`index.html`을 더블클릭하면 브라우저에서 열립니다. 글꼴은 인터넷이 연결돼 있을 때 Google Fonts에서 받아 오고, 연결이 없으면 기본 글꼴로 보입니다.

## 3. 내용 고치기

방법은 두 가지이고, 결과는 같습니다.

### 방법 A — 관리자 화면에서 고치기 (추천)

1. 오른쪽 위 **자물쇠(🔒)** 를 누릅니다.
2. 처음에는 **관리자 비밀번호 만들기** 창이 뜹니다. 8자 이상으로 정합니다.
3. **내용 편집** 탭에서 영역을 고르고 글을 고칩니다. 목록은 `＋ 추가`, `↑ ↓`, `삭제`로 다룹니다.
4. 위쪽 **저장하고 적용**을 누르면 지금 쓰는 브라우저에서 바로 반영됩니다.
5. **설정 파일·보안** 탭 → **설정 파일 내려받기 (config.js)** 를 눌러 파일을 받습니다.
6. 받은 파일로 사이트 폴더의 `config.js`를 **덮어쓰고 다시 올리면** 모든 방문자에게 반영됩니다.

> 중요: 4번까지만 하면 **내 브라우저에서만** 바뀐 것으로 보입니다. 5~6번을 해야 다른 사람에게도 보입니다.

### 방법 B — `config.js`를 직접 고치기

메모장 등으로 `config.js`를 열어 따옴표(`"…"`) 안의 글자만 바꾸고 저장한 뒤 새로고침(F5)합니다. 파일 안에 항목별 설명이 적혀 있습니다. (관리자 화면에서 내려받은 `config.js`에는 설명 주석이 없습니다.)

### 자주 고치는 곳

| 고칠 것 | 위치 (`config.js` / 관리자 화면 영역) |
| --- | --- |
| 학과·강의 제목 | `site` / 사이트 기본 정보 |
| 배지·부제·설명·버튼·일정 요약 | `hero` / 첫 화면 |
| 통계 숫자 | `stats` / 통계 카드 |
| 강의 장점 슬라이드 | `about.slides` / 프로그램 소개 |
| 첫 수업일·시간·장소 | `curriculum.schedule` / 커리큘럼·일정 |
| 주차별 내용·영상·과제 | `curriculum.weeks` / 커리큘럼·일정 |
| AI 도구·준비물 | `guide` / 수강 안내 |
| 투표 보기·신청서 항목 | `participate` / 참여하기 |
| 교수자 소개·사진·연락처 | `instructor` / 교수자 |
| 팝업 문구·표시 시간 | `popup` / 안내 팝업 |

- **수업 날짜**는 첫 수업일(`firstClass`)부터 7일 간격으로 자동 계산됩니다. 휴강·보강으로 한 주만 다르면 그 주차에 `date`(예: `"2026-05-07"`)를 넣습니다. 관리자 화면에서는 주차를 펼쳐 `＋ 이 주만 날짜·시간·장소 따로 지정`을 누릅니다.
- **과제**는 주차에 `assignment`를 넣으면 생깁니다. 마감은 `"2026-03-23T23:59"` 형식입니다.
- **교수자 사진**은 `images` 폴더를 만들어 사진을 넣고 `instructor.photo`에 `"images/파일이름.jpg"`를 적습니다.

## 4. 관리자 화면의 탭

| 탭 | 하는 일 |
| --- | --- |
| 내용 편집 | 사이트 정보와 각 섹션 내용을 화면에서 고칩니다. |
| 공지 | 공지를 올립니다. 첫 화면 바로 아래 공지사항 상자에 나타납니다. |
| 수강생 명단 | 수강생을 한 명씩 또는 여러 명(붙여 넣기·CSV) 등록하고, 수강 코드를 바꿉니다. |
| 내역 확인 | 출석·과제 제출·수강 신청 내역을 보고 엑셀용 파일(CSV)로 내려받습니다. |
| 설정 파일·보안 | 설정 파일 내려받기·불러오기, 원본으로 되돌리기, 관리자 비밀번호 변경. |

- **수강생 명단**: 명단이 비어 있으면 수강 코드만 맞으면 로그인됩니다. 명단을 등록하면 명단의 학번·이름과 일치해야 로그인됩니다. 초기 수강 코드는 제작 때 전달받은 값이며, 운영 전에 꼭 바꾸세요.
- **명단 보관**: 설정 파일에는 이름·학번 대신 알아볼 수 없는 지문(해시)만 들어갑니다. 읽을 수 있는 명단은 관리자의 브라우저에만 있으니 **명단 CSV 내려받기**로 따로 보관하세요. 다른 컴퓨터에서 명단을 고치려면 그 CSV를 다시 불러와야 합니다.
- **CSV 파일**은 엑셀에서 더블클릭하면 한글이 깨지지 않고 열립니다.

## 5. 수강생이 쓰는 기능

- **투표**: 보기를 누르면 막대그래프가 바로 바뀝니다.
- **수강 신청서**: 빠진 항목이 있으면 알려 줍니다.
- **내 강의실**: 학번·이름·수강 코드로 로그인 → 출석 체크, 과제 파일 제출.
- **달력**: 수업일과 과제 마감일이 표시되고, 날짜를 누르면 그날 수업이 나옵니다.

## 6. 꼭 알아 둘 한계 (서버가 없는 사이트)

이 사이트는 서버 없이 동작하도록 만들었기 때문에 다음과 같은 한계가 있습니다.

1. **기록은 각자의 브라우저에만 저장됩니다.** 수강생이 자기 휴대폰에서 한 투표·신청·출석·과제 제출은 교수자에게 전달되지 않습니다. 관리자 화면의 "내역 확인"에는 **그 브라우저에서 입력된 기록만** 보입니다. (예: 강의실 공용 컴퓨터 한 대에서 모두 입력한 경우)
2. **과제 파일은 어디에도 전송되지 않습니다.** 파일 이름·크기·제출 시각만 기록됩니다.
3. **로그인과 관리자 잠금은 화면을 가리는 수준입니다.** 비밀번호와 수강 코드는 지문(해시)으로만 저장되어 코드에서 바로 보이지는 않지만, 설정 파일은 누구나 내려받을 수 있고 짧은 비밀번호는 추측으로 풀릴 수 있습니다. 길고 다른 곳에서 쓰지 않는 비밀번호를 쓰고, 민감한 개인정보는 사이트에 넣지 마세요.
4. 그래서 화면에 "시범 운영 중" 안내 문구를 넣어 두었습니다 (`participate.apply.notice`, `classroom.notice`).

**실제로 기록을 모으려면** 외부 서비스 연결이 필요합니다.

- 수강 신청서만: `participate.apply.endpoint`에 신청서를 받을 주소(Google Apps Script 웹 앱, Formspree 등)를 넣으면 제출 내용이 그 주소로 전송됩니다.
- 투표 합산·출석·과제 파일까지: Supabase·Firebase 같은 서비스(백엔드) 연결이 필요합니다. 또는 과제 제출 버튼을 학교 LMS로 연결할 수 있습니다 (`curriculum.schedule.submitUrl`에 LMS 주소 입력).

실제 운영 전에는 `classroom.testMode`를 `false`로 바꾸세요. (`true`면 수업일이 아니어도 출석 체크가 됩니다.)

## 7. 배포 (인터넷에 올리기)

올릴 파일: `index.html`, `config.js`, `styles.css`, `app.js`, `admin.js` (+ 사진을 넣었다면 `images` 폴더)

**배포 전 점검**

- [ ] 강의 제목, 교수자 정보 등 `○○○` 예시 문구를 실제 내용으로 바꿨는지
- [ ] 관리자 비밀번호를 만들고, 그 상태로 내려받은 `config.js`로 교체했는지 (`admin.passwordHash`가 비어 있으면 누구나 자물쇠를 눌러 자기 브라우저에서 관리자 화면을 열 수 있습니다)
- [ ] 수강 코드를 바꿨는지
- [ ] `classroom.testMode`를 `false`로 바꿨는지

### 방법 1 — Netlify Drop (가장 쉬움)

1. <https://app.netlify.com/drop> 에 접속해 로그인합니다.
2. 사이트 폴더를 화면에 끌어다 놓습니다.
3. 주소(`…netlify.app`)가 만들어집니다. 내용을 고친 뒤에는 폴더를 다시 끌어다 놓습니다.

### 방법 2 — GitHub Pages

1. GitHub에서 새 저장소를 만들고 위 파일들을 올립니다 (Add file → Upload files).
2. 저장소 **Settings → Pages**에서 Source를 `Deploy from a branch`, Branch를 `main` / `(root)`로 고르고 저장합니다.
3. 잠시 뒤 `https://아이디.github.io/저장소이름/` 주소로 열립니다.
4. 내용을 고칠 때는 새 `config.js`를 같은 방법으로 올려 덮어씁니다.

### 방법 3 — 학교·학과 웹 서버

담당자에게 위 파일들을 전달하거나, FTP로 웹 폴더에 올립니다. 별도 프로그램 설치는 필요 없습니다.

### 배포 뒤 내용 고치는 순서

관리자 화면에서 수정 → 저장하고 적용 → 설정 파일 내려받기 → 서버의 `config.js` 교체. 새 `config.js`가 올라가면 관리자 브라우저에 남아 있던 예전 수정본은 자동으로 버려집니다.

## 8. 문제 해결

| 상황 | 해결 |
| --- | --- |
| 고친 내용이 다른 사람에게 안 보임 | 설정 파일을 내려받아 서버의 `config.js`를 교체했는지 확인합니다. |
| 고친 뒤 화면이 이상해짐 | 주소 끝에 `?reset`을 붙여 엽니다 (예: `…/index.html?reset`). 이 브라우저의 수정본을 버리고 `config.js` 원본으로 돌아갑니다. |
| 관리자 비밀번호를 잊음 | `config.js`에서 `admin.passwordHash` 값을 `""`로 비우고 다시 올린 뒤, 자물쇠를 눌러 새로 만듭니다. |
| 팝업·폭죽을 다시 보고 싶음 | 주소 끝에 `?welcome`을 붙여 엽니다. |
| `config.js`를 고친 뒤 화면이 비어 있음 | 따옴표나 쉼표가 빠졌을 가능성이 큽니다. 고치기 전 파일로 되돌려 다시 시도합니다. |
| 날짜가 하루씩 어긋남 | `firstClass`가 실제 첫 수업일(화요일)인지 확인합니다. |

## 9. 서버 저장 (Railway + PostgreSQL)

`server.js`가 사이트 파일을 내보내고, 방문자와 관리자가 만든 데이터를 PostgreSQL에 저장합니다.
DB가 연결되지 않은 곳(파일을 직접 연 경우 등)에서는 예전처럼 각자의 브라우저에만 저장됩니다.

### Railway 설정
1. 프로젝트에 **PostgreSQL**을 추가합니다 (New → Database → Add PostgreSQL).
2. 사이트 서비스의 **Variables**에 `DATABASE_URL`을 추가하고 값으로 `${{Postgres.DATABASE_URL}}`을 넣습니다.
3. (권장) `ADMIN_PASSWORD`에 관리자 비밀번호를, `SESSION_SECRET`에 아무 긴 문자열을 넣습니다.
4. 다시 배포되면 `https://사이트주소/api/state`가 `{"db":true,...}`로 응답합니다.

| 변수 | 필수 | 설명 |
| --- | --- | --- |
| `DATABASE_URL` | 예 | PostgreSQL 연결 주소. 없으면 저장은 각자 브라우저에만 됩니다. |
| `ADMIN_PASSWORD` | 권장 | 관리자 비밀번호. 넣으면 config의 비밀번호 지문 대신 이 값으로 확인합니다. |
| `SESSION_SECRET` | 권장 | 로그인 토큰 서명용. 없으면 재배포할 때마다 다시 로그인해야 합니다. |
| `PGSSL` | 아니오 | DB 연결에 SSL이 필요하면 `1` |

### 서버에 저장되는 것
| 데이터 | 저장 위치(테이블) |
| --- | --- |
| 관리자가 고친 내용 전체 (공지·설문·달력 일정·포트폴리오·팝업·커리큘럼·수강 안내 등) | `site_kv` |
| 설문 응답 | `poll_votes` |
| 수강 신청서 | `applications` |
| 출석 | `attendance` |
| 과제 제출 기록 (파일 이름·크기·시각·메모) | `submissions` |

- 과제 **파일 자체는 저장하지 않습니다.** 파일 이름과 제출 시각만 기록합니다.
- 관리자가 한 번이라도 저장하면 그때부터 DB의 수정본이 화면에 쓰입니다. 그 뒤에는 `config.js` 파일을 고쳐도 화면에 반영되지 않습니다. 원본으로 돌아가려면 관리자 화면 → 설정 파일·보안 → "수정본 지우고 config.js 원본으로 되돌리기".

### 내 컴퓨터에서 실행
```bash
npm install
npm run dev
```
`npm run dev`는 메모리 DB로 실행합니다(끄면 데이터가 사라짐). 브라우저에서 `http://localhost:5173`을 엽니다.
